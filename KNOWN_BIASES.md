# Known Biases Register

Every backtest output (plot, table, summary) must be accompanied by this
register, per SPEC.md principle #4. This file is append-only in spirit:
entries get their mitigation status updated as phases land, but rows are not
deleted just because they've been addressed — mark them "Mitigated" instead
so the history of what was considered stays visible.

Populated in Phase 0 from design decisions already made in SPEC.md, before
any data has been touched, so the register is never empty. Update it every
time a phase introduces, discovers, or mitigates a bias.

| # | Bias | Where it enters | Direction of effect | Magnitude estimate | Mitigation status |
|---|------|------------------|----------------------|---------------------|--------------------|
| 1 | **Survivorship bias in price data.** `yfinance` (and similar free sources) silently drop tickers that delisted. | Prices ingest (Phase 1, implemented — `garp.ingest.prices`) | Inflates backtest returns — the losers that went to zero or got delisted-cheap are missing from the return series. | Large for small caps; small-cap delisting/failure rates are materially higher than large-cap, and this is exactly the population a GARP-on-small-caps screen selects into. | **Not started.** `garp.ingest.prices.fetch_price_history` logs a `yfinance_survivorship_bias` warning on every call as a standing reminder, but the underlying gap is unaddressed — restricted to Phase 1 plumbing/dev only per SPEC. Final results require a source with delisted coverage (Sharadar SEP/SFP, or Tiingo/Polygon with delisting confirmed). |
| 2 | **No free point-in-time analyst consensus estimates exist.** | Growth-leg factor design (Phase 1/3) | Not a directional bias but a scope substitution: the backtest tests "GARP using trailing realized growth," a related but different strategy from classic PEG (forward consensus / trailing P/E). Results should not be read as validating or refuting classic PEG. | N/A — methodology decision, documented so it isn't mistaken for the classic screen. | **Mitigated by design.** Option 1 from SPEC (trailing 3–5yr realized revenue/EPS CAGR from EDGAR) is the implemented default; growth leg is pluggable so a PIT-estimates source could be swapped in later without touching the engine. |
| 3 | **No free point-in-time index constituent history for S&P SmallCap 600 / Russell 2000.** | Universe construction (Phase 2, not yet built) | Ambiguous a priori. A synthetic universe (EDGAR filers ranked into a market-cap band + liquidity/price filters) will both admit names the real index excluded and miss names it included, in ways that could push results either direction. | Unknown until built; expect moderate divergence from the true index history, especially around reconstitution dates and micro-cap boundary names. | **Planned.** SPEC mandates the synthetic-universe substitution be documented prominently wherever it's used, not silently assumed to equal the real index. Not yet implemented. |
| 4 | **EDGAR filer coverage near delisting/bankruptcy may lag or stop before the terminal event.** | Fundamentals ingest (Phase 1) | The last point-in-time fundamentals snapshot for a distressed company can be stale relative to its actual deteriorating condition, making the pre-delisting factor scores look better than reality. | Small to moderate; concentrated in the (small) subset of names that delist per period. | **Not started.** Phase 5 requires flagging any candidate with no filing in >120 days; the same staleness signal should be surfaced historically wherever it affects a backtest period, not just live screens. |
| 5 | **XBRL concept-mapping errors could pull restated instead of as-first-reported values.** | Fundamentals ingest, concept-mapping layer (Phase 1 — `garp.ingest.concepts`) | If a fallback in the tag-mapping chain ever resolves to a value only available after a later restatement, future information leaks into the past — this is principle #1 and #3 violated simultaneously. | Potentially large if mis-implemented, and silent — this is the highest-priority correctness risk in the whole project. | **Partially mitigated.** Implemented: extraction keys strictly on `filed` (never `end`/period-end), an unmapped concept logs a `concept_unmapped` warning instead of being null-filled, and 10-K/A amendments fall out correctly as later, independently-dated rows (see tests/test_concepts.py, tests/test_pit.py). Not yet covered: the fallback tag chains themselves are a best-effort first pass (see module docstring — `total_debt` in particular has no single canonical tag) and haven't been audited against a large, diverse company sample; live-tested against real filings (Apple, Oxford Industries, Kulicke & Soffa) and already caught one real unmapped case (`total_liabilities` for Oxford Industries). |
| 6 | **Pre-adjusted (split/dividend-adjusted) price series compute adjustments with full-history hindsight.** | Prices ingest (Phase 1 — `garp.ingest.prices`) | A price series adjusted using a stock split that hasn't happened yet as of date `T` is a look-ahead leak into factors computed on price history (e.g. dollar volume, price filters). | Small per-instance but insidious and easy to introduce accidentally via a convenience API that returns pre-adjusted data by default. | **Mitigated.** Unadjusted OHLCV and a separate corporate-actions table are stored; `compute_adjusted_close(..., asof=T)` computes the adjustment at query time using only actions with `ex_date <= T`, tested against both synthetic cases and real KLIC dividend/price history (tests/test_prices.py). Caveat: the dividend adjustment is the standard `1 - div/prior_close` approximation, not exact reinvestment accounting. |
| 7 | **Universe excludes REITs and financials initially.** | Universe construction (Phase 2, not yet built) | Results generalize only to the non-financial, non-REIT small-cap universe. Not a look-ahead/survivorship bias, but a scope limitation that must be stated alongside any result so it isn't read as "small caps generally." | N/A — deliberate scope decision, revisit with sector-specific accounting handling later per SPEC. | **By design.** Documented here so it's visible next to results, not just in code. |
| 8 | **No free point-in-time CIK↔ticker history.** SEC's `company_tickers.json` is a current-day snapshot: it has no record of what ticker (if any) a CIK had on a past date. | Identity mapping (Phase 1 — `garp.ingest.tickers`) | A CIK that changed ticker (rebrand, uplisting, post-bankruptcy relaunch) has no free record of *when*; joining "ticker as of date T" against this table risks silently using today's ticker for a historical row. | Small in aggregate (ticker changes are rare relative to filings), but a real gap for any name that did change tickers within the backtest window. | **Not started.** Documented in the module docstring: downstream code should join on CIK wherever possible and treat the ticker column as "best current label," never as proof of historical validity. `submissions/CIK##########.json`'s `formerNames` field could partially help for company-name changes; not implemented. |

---

**Legend for mitigation status:** `Not started` / `Planned` (mitigation designed but not implemented) / `Partially mitigated` / `Mitigated` (implemented and tested) / `By design` (deliberate scope limit, not a bug to fix).
